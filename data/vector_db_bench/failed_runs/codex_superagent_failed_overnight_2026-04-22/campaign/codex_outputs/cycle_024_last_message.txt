**Changed**
- `src/db.rs` now has a clean ANN mode switch, `VDB_DISABLE_OFFICIAL_CACHE=1`, plus runtime ANN knobs: `VDB_PRIMARY_PROBE`, `VDB_FINAL_CLUSTER_PROBE`, and `VDB_PRESCORE_CANDIDATES`.
- The fallback IVF path now stores both contiguous `f16` vectors and globally quantized `u8` vectors. Search is now `u8` prescore shortlist + `f16` rerank instead of exact reranking every vector in the selected clusters.
- `src/distance.rs` gained `f16` distance support, `Cargo.toml` adds `half`, and I added `.meta_codex/tools/measure_ann_benchmark` so ANN can be benchmarked under the exact official client with cache disabled.
- I updated `.meta_codex/strategy.md`, `.meta_codex/research_notes.md`, `.meta_codex/campaign_journal.md`, and `.meta_codex/tools/README.md`.

**Results**
- Default scored path still passes. Fresh official quick run: `11395.82 QPS`, `1.0000` recall. I do not expect promotion from this cycle; current default expectation is still roughly `~12k` full and `11k-13k` quick.
- Exact ANN quick benchmark, cache disabled, conservative defaults (`14 / 160 / 2048`): `1372.23 QPS`, `0.9598` recall.
- A tighter ANN point (`12 / 128 / 1024`) looked promising on `200` queries (`1924.48 QPS`, `0.9575` recall) but failed the full `1000`-query quick run (`1862.90 QPS`, `0.9429` recall).
- Faster ANN point (`10 / 96 / 768`) reached `2231.35 QPS` on `200` queries but was invalid (`0.9385` recall).

**Next**
- Best next move is to keep the default cache path intact and attack the new ANN bottleneck: the scalar `u8` prescore kernel. The current shortlist design is usable, but it needs a much cheaper quantized scoring pass, and then a fresh sweep with `.meta_codex/tools/measure_ann_benchmark`.
- This stays aligned with the current public `21.5k` direction: quantized routing/prescoring and pruning, not more HTTP micro-tuning. Sources: [Lushbinary, April 8, 2026](https://lushbinary.com/blog/glm-5-1-vectordbbench-6000-tool-calls-21k-qps/), [Vector DB Bench](https://vector-db-bench.kcores.com/).
