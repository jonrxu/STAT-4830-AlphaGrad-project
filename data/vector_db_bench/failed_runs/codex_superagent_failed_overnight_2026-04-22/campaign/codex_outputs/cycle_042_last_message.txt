**Current Expectation**

- The new PQ branch is better than old global PQ, but still not viable. On a primed local `300`-query sweep at `14 / 136`, `primary_residual` improved recall up to `0.9457` at `2048` candidates, versus `0.9127` for same-point global PQ, but QPS still fell to roughly `2.8k-5.2k` and never reached the `0.95` threshold. ANN stats at `14 / 136 / 2048` still showed about `11.9k` scanned vectors/query, with scan time around `605 us`, so it is not cutting the real bottleneck.
- I did not run the exact ANN benchmark for that branch because the local primed gate already failed. Default official behavior is still valid: `build_project` succeeded, `run_correctness_test` passed at `1.0000`, and a fresh serial quick `run_benchmark` measured `10703.26 QPS`. Practical expectation is still low-`10k` to low-`12k` on the scored path, with exact ANN still roughly mid-`5k` class.

**Next Best Move**

Do not spend another cycle widening primary-residual PQ budgets. The next credible move is a shortlist design that materially reduces scanned vectors before the expensive scan kernel runs, or a much cheaper ADC path if PQ stays in play. The harness is now set up to test that quickly with primed/stats sweeps.
