# Strategy

- Optimize for a valid `22000+ QPS` solution, not a pretty exact-search baseline.
- Treat `21500 QPS` as the public SOTA target to beat and `22000 QPS` as the working campaign goal.
- Treat the current transport/cache branch as a plateaued scorer, not the end state. Exact official runs are still clustering around roughly `12k` full and low-`13k` quick.
- Cycle-54 made `VDB_SPLIT_CACHED_SEARCH_RESPONSE` default-on because it was the first transport knob in a long time to transfer across both the reqwest phase probe and the exact official breakdown wrapper. On the same host, `sweep_official_breakdown VDB_SPLIT_CACHED_SEARCH_RESPONSE off 1` moved exact quick breakdown from about `10479.11` to about `11954.86 QPS` while cutting cached-search `avg_search_read_request_us` from about `751.09` to about `464.76`, and env-forced plain quick samples reached about `10993.03` and `13382.27`. Keep the new default, but do not claim the scorer is solved: the no-env full local run still landed only about `10464.77`, so the next transport work should stabilize around this split-response path with exact A/Bs, not reopen early-response ideas or other dormant read-path tweaks blindly.
- The same cycle also finished the obvious residual follow-on: `primary_residual` can now reuse flat vector-radius metadata in the same shared residual space. That did not revive the branch. At `14 / 144 / 416` on the primed local `300`-query gate, residual-radius improved from about `5523.57 QPS`, `0.9507` recall with radius off to about `5676.25`, `0.9510` with radius on, but it still pruned only about `2.35` vectors/query and the fast exact `200`-query benchmark fell to about `4469.42`, `0.9695`. Keep the branch benchmarkable, but do not spend another exact ANN gate on it again until the same local point prunes materially more than this.
- Only spend more transport cycles when the exact official breakdown wrapper shows a real win on the fully buffered fast-hit path. Do not keep chasing dormant early-hit shortcuts just because the reqwest probe likes them.
- Move the next substantive Rust work toward real ANN shortlist generation again: compressed storage, quantized routing / prescoring, and smaller rerank sets.
- Keep the default scored cache path intact while ANN work is immature, but make ANN benchmarkable under the exact official client with cache explicitly disabled so search-side tuning can move quickly.
- The current quantized fallback path now has AVX2/F16C search kernels, AVX2 `f32` centroid routing, chunked `u8` scan filtering, and a kept ANN default of `14 / 138 / 384` with `u8` routing default-on. That is still only a mid-`5k` exact band, not a public-target contender.
- Cycle-53 added `VDB_QUANTIZED_PRESCORE_MODE=primary_residual` plus ANN wrapper/sweep support so the flat prescore stage can score shortlisted vectors in a primary-residual `u8` space instead of the old global `u8` space. The corrected shared-scale version is locally real on the no-radius branch: on the primed local `300`-query gate, `14 / 144 / 416` improved from about `5521.19 QPS`, `0.9503` recall in global mode to about `5896.86`, `0.9507` in primary-residual mode. It did not transfer on the exact gate: the same branch reached about `4888.18 QPS`, `0.9690` on the fast exact `200`-query check and about `4877.22`, `0.9557` on the fast exact `1000`-query check, both below the kept flat exact band. Keep the mode and harness knobs for future residual work, but do not spend another full exact ANN gate on it again until the residual branch can reuse compatible lower bounds or otherwise beat the flat exact `200`-query baseline first.
- Cycle-52 added `VDB_ENABLE_LEAF_SUPERCLUSTER_ROUTING` plus ANN wrapper/sweep support so the workspace can route through a second k-means layer built over the existing leaf centroids instead of only the original per-primary buckets. The first retune says the routing family is directionally real but not exact-promotable yet: on the primed local `300`-query gate, `24 / 144 / 416` improved from about `4914.48 QPS`, `0.9560` recall on the flat route to about `5249.04`, `0.9557` with leaf-supercluster routing, but the fast exact `200`-query ANN check reached only about `4028.16`, `0.9675` versus the same-point flat baseline about `4073.65`, `0.9675`. Keep the routing layer and harness knobs for future work, but do not spend the full exact ANN gate on it again until a sharper budget retune or a pruning follow-on beats the exact `200`-query baseline first.
- Cycle-51 added `VDB_PRIMARY_CLUSTERS` plus ANN wrapper/sweep support so the workspace can test `P x N` IVF geometries without hand-editing Rust. The first serious recheck says geometry alone is still not enough: `384 x 64`, `primary_probe 20`, `cluster_probe 192`, `prescore 384` reached about `5694.80 QPS`, `0.9507` recall on the primed local `300`-query gate with about `12.15k` scanned vectors/query, but the exact fast `1000`-query ANN benchmark fell to about `4046.72`, `0.9568`. Keep the knob for future structural work, but do not spend another exact gate on higher-primary geometry alone unless a stronger routing or training change explains the resident-state transfer loss first.
- Cycle-50 added `VDB_LOCAL_SUBCLUSTER_ROUTING` plus ANN wrapper/sweep support so the workspace can A/B the parked local-subcluster selector with quantized versus exact local-centroid routing. The first primed local checks say raw routing precision alone is not the unlock: at `14 / 138 / 384`, `target 24 / probe 1` stayed around `0.651` recall with about `3.75k` scanned vectors/query for both `u8` and `f32`, `probe 2` stayed around `0.8467` with about `6.75k` scanned/query, and the adaptive `--enable-cluster-prune` point stayed around `0.9483` with about `12.0k` scanned/query and about `541` selected subclusters/query for both modes. Keep the knob for future routing studies, but do not spend another exact ANN gate on local-centroid precision alone unless it is paired with a stronger subcluster signal.
- The same cycle briefly rechecked a direct-buffer transport read rewrite on the exact default fast-hit path and reverted it. Exact breakdown only moved from about `11279.98` to about `11323.56 QPS` while average cached-search `read_request` time worsened from about `404.76 us` to about `545.59 us`, so do not keep server read-path micro-tweaks without repeated exact evidence on the fully buffered fast-hit path.
- Cycle-49 added a new residual-aware coarse shortlist mode, `VDB_COARSE_PRESCORE_MODE=residual`, and wired it through the ANN wrappers plus the coarse sweep helper. The first primed local recheck at `14 / 138 / 384` says the idea is directionally better than the parked raw coarse branch but still not promotable: cluster-scope residual `32 / 2048` reached about `4716.29 QPS`, `0.9367` recall with about `422.76 us` scan time and about `2046` rescored candidates/query, while primary-scope residual `32 / 2048` reached about `4766.76`, `0.9333` with scan about `416.20 us`. Keep the mode and harness support, but do not spend the exact ANN gate on residual coarse again until either the selector cost drops materially or another signal pushes the same branch near validity.
- Cycle-48 added `VDB_SECONDARY_CLUSTERS` plus ANN wrapper/sweep support so the workspace can re-test `256 x N` geometry without ad hoc env juggling. The first revisit parked geometry-only tuning again: at `14 / 138 / 384`, moving from `64` to `96` or `128` secondaries cut local scanned vectors from about `12.05k` to about `8.85k/7.17k`, but recall collapsed to about `0.933/0.923` and QPS fell to about `5.48k/4.94k`; nearby `72/80/88` points with `138-152` probes still stayed invalid around `0.938-0.949`. Keep the knob for future structural work, but do not spend another cycle on geometry-only sweeps unless a stronger routing or training signal changes the recall curve first.
- The same cycle also tried deterministic farthest-first k-means seeding and reverted it. Although a primed local `300`-query run at `14 / 136 / 320` became valid at about `6835.51 QPS`, `0.9510`, the exact fast `1000`-query gate fell to about `4783.53`, `0.9534`, and first-search build time roughly tripled from the old `~4.2 s` band into about `11.3 s`. Do not revisit centroid seeding alone unless it improves exact transfer, not just local recall.
- Cycle-45 showed the fast exact ANN gate is noisier than the journal history suggested. Use `.meta_codex/tools/measure_ann_benchmark_stability` before promoting any narrow ANN point or routing delta that is only a few percent.
- The same cycle-45 stability rerun finally made the routing branch promotable at the kept flat point. A 3-run exact-fast check at `14 / 138 / 384` measured about `5041.16` mean QPS, `0.9531` with explicit `u8` routing off versus about `5601.15`, `0.9532` with explicit `u8` routing on, so the fallback now keeps `u8` routing on by default. Use explicit `--disable-u8-routing` / `--enable-u8-routing` or `.meta_codex/tools/compare_ann_u8_routing` for A/Bs.
- The same cycle-45 local primed `300`-query search-only gate said the new batch cutoff filtering is directionally real even though local QPS stayed noisy: at `14 / 138 / 384` with `u8` routing, average scan time moved from about `219 us` to about `206 us` with recall unchanged on that local sample. Treat that as a small transfer candidate, not as the main unlock.
- Cycle-47 ruled out two more shortlist-pruning side paths on the live `u8` branch before paying the exact gate. A primed `300`-query local sweep of true global local-subcluster probing at `14 / 138 / 384` (`target 24-48`, global probe `96-128`) only reached about `0.59-0.75` recall despite `5.4k-7.6k` QPS, so do not revive the current local-subcluster implementation just because a smaller global probe looks fast.
- The same cycle added default-off block-bound pruning hooks to the Rust path and ANN harness (`--enable-block-bound-prune`, `--block-bound-dims`), but the first flat local A/B parked the idea immediately. At `14 / 138 / 384` on the primed `300`-query local gate, the flat no-radius baseline measured about `5775.61 QPS`, `0.9480` recall with about `255.70 us` scan time and `0` pruned vectors/query, while block-bound pruning with `8` dims fell to about `4836.42`, the same `0.9480`, with scan time about `282.13 us` and only about `0.25` pruned vectors/query. Treat this first block-box implementation as parked until there is a materially stronger bound or a much tighter block ordering.
- Cycle-46 made the parked coarse-shortlist branch cheaper to test but not alive enough to validate exactly. The new batched arbitrary-width `u8` subspace scan and cutoff-aware exact rescoring lifted the old cluster-scope `32 / 2048` local point at `14 / 138 / 416`, but a paired 2-run primed `300`-query comparison still only averaged about `4880.11 QPS`, `0.9390` recall with about `395 us` scan time versus the flat baseline about `6385.01`, `0.9480` with about `203 us`. Scanned vectors stayed essentially unchanged at about `12.05k/query`, so do not spend the exact ANN gate on the coarse branch again until the signal itself improves, not just the selector kernel.
- Cycle-46 also added `.meta_codex/tools/compare_ann_coarse_shortlist`, a serial local A/B helper that repeats the same search-only point with and without coarse prescore and summarizes paired QPS / recall / ANN scan metrics. Use it before hand-running coarse baseline comparisons again.
- Cycle-36 re-swept the wider flat region (`cluster_probe 138-144`, `prescore 352-448`) on the fast exact gate and still topped out only at about `5398.56 QPS`, `0.9554` recall (`14 / 144 / 416`), below the cycle-35 best `5529.23`. Treat the current flat IVF fallback as plateaued again; do not spend another cycle on small flat budget sweeps unless a new routing or shortlist mechanism changes the scan-cost shape first.
- The new opt-in `VDB_COARSE_PRESCORE_DIMS` branch is benchmarkable through the ANN wrappers, but the current ordered-dimension early-abort implementation is not yet a win. On the local preload/search-only harness, `coarse_prescore_dims=32` pruned about `10.5k` of `12.4k` scanned vectors/query from full-distance accumulation while still regressing badly to roughly `4.6k QPS`. Keep it experimental only and do not promote or resweep it until the kernel cost is understood.
- Cycle-37 rewrote that early-abort inner loop with an AVX2 upper-bound kernel and a cheaper local cutoff in the scan loop, but the branch still stayed well below the flat baseline. A fresh local sweep over `coarse_prescore_dims=8/12/16/24/32/48/64` at `14 / 138 / 416` topped out only around `4629.90 QPS` (`12` dims) versus the plain flat baseline around `5977.03`, all at the same `0.9514` recall. Treat ordered-dimension early abort as still parked until there is either a substantially cheaper SIMD implementation or a different approximate shortlist stage behind it.
- Cycle-38 repurposed that same opt-in coarse branch into a true compact subspace shortlist: scan all shortlisted vectors in `coarse_prescore_dims`, keep only `coarse_prescore_candidates`, then run full `u8` prescore on that smaller set before `f16` rerank. It is now closer to the right architecture class, and the sweep helper can vary both dims and coarse shortlist budget, but the current surrogate is still not promotable. Fresh local runs at `14 / 138 / 416` cut full `u8` rescoring to `1536-2048` candidates/query while recall collapsed to roughly `0.69-0.91` and search-only QPS fell into roughly `3.0k-3.9k`. Do not pay the exact ANN gate for this branch again until there is a materially better coarse signal or a cheaper shortlist-selection kernel.
- Cycle-39 strengthened that same experimental shortlist branch in the right direction: it now keeps a small coarse shortlist per selected range instead of one global low-dimensional heap, and each coarse scan uses cluster-specific dimensions rather than one global dimension ordering. The new signal is materially better. On the local preload/search-only harness at `14 / 138 / 416`, `24 / 1536` improved from the old roughly `0.68` recall into roughly `0.91`, and `32 / 3072` reached about `0.9491` recall. But the branch is still too slow to matter, topping out only around `4.2k-4.9k QPS`, well below the flat baseline around `6.7k`. Keep the code experimental, but do not spend the exact ANN gate on it again until either the shortlist selector gets materially cheaper or a stronger residual-aware / learned coarse signal pushes valid local points back toward the flat baseline.
- Cycle-43 split that same coarse shortlist branch into explicit `cluster` and new `primary` scopes and added upper-bound early exit inside the compact subspace scan. The new `--coarse-prescore-scope` harness knob is useful, and the early-exit kernel lifted fresh primed local valid points at `14 / 138 / 416` to about `4041.94 QPS`, `0.9515` (`cluster`, `32 / 1536`), `4212.54`, `0.9560` (`cluster`, `32 / 2048`), and `4035.15`, `0.9545` (`primary`, `32 / 2048`). That is still well below the flat local baseline band. Keep both coarse scopes experimental only and do not spend the exact ANN gate on them again unless the shortlist selector gets materially cheaper.
- Cycle-41 corrected the `VDB_ENABLE_PQ_PRESCORE` story: the old cycle-40 local "PQ win" was a false positive because the default vector-radius branch was still active whenever PQ was enabled, so those measurements were really smaller-budget flat runs. The Rust path now treats PQ prescore and vector-radius pruning as mutually exclusive, and the ANN wrappers now force that override explicitly when `--enable-pq-prescore` is used.
- With real PQ active, the current global codebooks are not promotable. On the local preload/search-only harness, `14 / 136 / 352` now measures about `5981.98 QPS` but only `0.6920` recall, and a fresh local sweep at `14 / 136` only reached about `0.9340` recall even with `3072` prescore candidates while QPS fell to about `3177.49`. Treat this global PQ branch as parked again until there is a materially stronger signal, such as residual-aware or cluster-local PQ, not just a budget resweep.
- Cycle-42 repurposed that PQ experiment into a default-off `primary_residual` mode and extended the local sweep harness so `sweep_ann_search_only` can now pass `--prime-build` and stats flags through to each point, while all ANN PQ wrappers now accept `--pq-mode`. The new signal is better than global PQ on the same local sample, but it is still not alive enough to justify the exact ANN gate. On a primed `300`-query local sweep at `14 / 136`, `primary_residual` reached about `0.9457` recall at `2048` prescore candidates versus the same-point global PQ around `0.9127`, but QPS still collapsed to about `2.8k-4.0k` and ANN stats still showed roughly `11.9k` scanned vectors/query with scan time around `605 us`. Treat primary-residual PQ as parked too until the branch either cuts scanned vectors materially or gets a substantially cheaper ADC / shortlist kernel.
- Fresh cycle-38 transport rechecks say the default scored path is still client-limited on this host. A new exact default benchmark breakdown measured about `10491.63 QPS`, `1.0000` recall with `1100/1100` search requests still landing on the full-body fast-hit path and search-side server time still dominated by `read_request` rather than `process_request`. The tiny-base dummy official-client ceiling also rechecked at only about `10833.42 QPS`. Treat that as another reason not to burn a full cycle on transport-only micro-tuning unless a branch first moves the official-client ceiling itself.
- Cycle-33 added a fast exact ANN gate: `measure_ann_benchmark --fast` and `sweep_ann_benchmark --fast` now skip the request/ANN stats wrapper and call the official benchmark directly. Use that fast mode for QPS decisions, and only pay the slower stats path when you need anatomy.
- The now-default `u8` routing branch still needs explicit serial A/Bs when a cycle wants to question it. Cycle-45 stabilized `14 / 138 / 384`, but do not assume the same gain transfers automatically at `138-146` probes or different prescore budgets just because the local harness likes them.
- The local preload/search-only harness now supports optional server request stats and ANN-internal stats via `measure_ann_search_only --include-request-stats --include-ann-stats`. Use it to separate request overhead from steady-state ANN work before paying exact-wrapper time.
- The exact official ANN wrapper now also exposes ANN-internal stats through `measure_ann_benchmark`, because `measure_official_benchmark_breakdown` records `VDB_ANN_STATS_PATH` alongside request stats. Use that exact path when a branch looks locally interesting but the failure mode is still unclear.
- The new ANN-local stats show the current valid `14 / 136 / 480-576` region still scans about `12.3k-12.4k` vectors per query, with scan time dominating rerank and routing still non-trivial. Any next Rust change should cut scanned vectors materially, not just shave a few microseconds from rerank.
- Search-only wins are still transferring only partially. Fresh cycle-30 local runs around `14 / 136 / 480-512` reached roughly `6.2k QPS` at valid recall, while clean exact official ANN quick runs topped out at `5140.29 QPS`. Treat the exact wrapper as the decision gate and treat the local harness as a culling tool, not as promotion evidence.
- Cycle-31's new default fallback scan order adds per-vector quantized centroid radii plus radius-band scanning inside each selected cluster. On this workspace it moved the current exact ANN baseline from about `4101.72` to `4294.20 QPS` at valid recall for `14 / 136 / 480`, while local preload/search-only jumped from about `4.7k` to `6.3k`. Keep the branch, but do not overclaim it: ANN stats show it is still pruning only about `3.6` vectors/query on average, so most of the gain is locality/order cleanup rather than the final pruning unlock.
- Cycle-32's local-subcluster follow-on did not transfer. Extending radius-band scans into the experimental local-subcluster path prunes only about `11-12` vectors/query on the exact wrapper while pushing selected subclusters to about `538` and exact scan time to about `422 us`, materially worse than the flat baseline's roughly `270 us`. Do not keep iterating on this local-subcluster path unless the next change attacks range-fragment overhead or uses a genuinely stronger routing signal.
- The failed cycle-26 experiments still matter: default-on cluster pruning was slower, `256 x 128` and `256 x 256` coarse layers regressed, and the old naive u8 secondary-routing swap regressed. Cycle-33's new explicit full u8-routing branch did transfer when explicitly enabled, so the next routing work should build on that branch or explain the remaining no-env discrepancy before spending more cycles on geometry changes.
- The first cycle-27 batched multi-candidate u8/f16 kernel attempt also regressed on the exact wrapper and was reverted. Do not assume four-at-a-time batching is a win on this AVX2 host without a microbenchmark or search-only proof first.
- A second cycle-28 batch attempt regressed too and was also reverted. Do not spend another cycle on scan/rerank batching unless a dedicated local microbenchmark shows a clear win before exact validation.
- The hybrid seed-then-locality cluster-prune branch barely prunes on this workload. Keep it as an experiment only; the data says the next real gain needs a stronger pruning signal than the current centroid-radius lower bound.
- A cycle-35 follow-on that combined the flat cluster-prune path with vector-radius scanning also regressed on the exact fast gate and was reverted. Do not spend another cycle merely composing the existing weak prune signals.
- The new cycle-30 local-subcluster branch is now benchmarkable, including exact-wrapper support, but its adaptive prune still scans essentially the full `~12.4k` vector budget on valid points. Do not spend another cycle on this exact local-subcluster implementation unless a tighter lower bound or a different routing signal is ready first.
